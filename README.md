# Jev Othello

TypeSafe AI の評価モデル Jev とローカルで対戦するオセロです。ブラウザへ API キーを渡さず、Node.js サーバーから公式 SDK を呼びます。

## 必要なもの

- Node.js 24 以降
- npm
- Doppler CLI
- Doppler に設定済みの `TYPESAFE_API_KEY`

## 起動

```sh
npm install
doppler run -- npm start
```

`http://127.0.0.1:3000` を開きます。サーバーはループバックアドレスだけで待ち受けるため、同じPCからのみ接続できます。

型チェック:

```sh
npm run check
```

## 利用上限

初期値では、1回のサーバー起動につき Jev を最大80回、1分あたり最大20回呼び出します。上限は環境変数で変更できます。

```sh
JEV_MAX_REQUESTS=40 JEV_REQUESTS_PER_MINUTE=10 doppler run -- npm start
```

上限はサーバーを再起動するとリセットされます。外部公開用の永続的なレート制限ではなく、ローカル利用時の誤操作・ループ対策です。

## Jev への渡し方

Jev は reasoning をしないため、精度はプロンプトの作り方にほぼ全面的に依存します。`src/server.ts` では次の設計を取っています。

- **候補手のラベルは棋譜表記**（`f5`, `c4`）。Jev が事前学習で見ているオセロの表記に合わせ、定石知識を引き出します。
- **盤面は座標付きで描画**し、白が打てるマスを `*` で示します。候補ラベルと盤上の位置を対応づけるための読み替えを Jev にさせません。
- **候補手の説明は構造化 JSON**。全候補で同じキー・同じ順序（マス種別、返す枚数、着手後の相手の合法手数、相手に角を与えるか、隣接する角の所有者）を並べ、比較を安定させます。角・X打ち・C打ちの意味は `glossary` として state 側に置き、候補側には事実だけを載せます。
- **フェーズ別の指示**。序盤は枚数を取らない、終盤は取る、というオセロの反転する原則に合わせて指示文を切り替えます。
- **1リクエストで2つの質問**。「最善手はどれか」と「最悪手はどれか」を同時に聞き、返ってきた確率分布を `最善度 - 0.5 × 悪手リスク` で合成して着手を決めます。SDK は1リクエストに複数の質問を載せられるため、API 消費は1手あたり1回のままです。
- **棋譜履歴を送信**。ブラウザ側が保持する手順（`f5d6c3...`）を state に含めます。

プロンプトを調整する場合は `phaseGuide`、`glossary`、`describeCandidate`、`questions` の4箇所が入口です。
